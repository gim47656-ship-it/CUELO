CUELO Continue omp terminal sessions in the browser and back

History, accounts and model settings stay shared between the omp (oh-my-pi) CLI and the browser. CUELO also aims to turn mistakes and blockers from real work into memory, rules and procedures for the next task.

View source on GitHub Run from source

Run locally on Linux. Install from GitHub source or the cuelo package on npm. Node.js and Bun are required.

What CUELO is for

  1. Record what happened

    A failure or blocker is written down from what was actually observed.

  2. Change only the cause

    The part that caused it is updated: a memory, a rule, or a procedure.

  3. Carry it into the next task

    The next task starts with that change in its context.

  4. Check that it stopped

    It counts only if the problem does not come back. If it does, start again at step 1.

Saving a record is not treated as the improvement itself. This is the goal the project works toward, not a measured result.

How CUELO works

CUELO is a local web UI for omp (oh-my-pi) and an inspectable multi-agent harness for coding work. It keeps your terminal workflow instead of replacing it with a separate chat app.

  • Same sessions as the CLI — CUELO runs omp's own SDK inside a local web server and shares the ~/.omp/agent sessions, credentials and model settings with the CLI. It does not scrape CLI output, so a session started in the terminal continues in the browser and back.
  • Delegation you can inspect — A Main agent owns requirements and the final judgement and delegates slices to Maker agents; guards check assigned file boundaries. Each task gets a card with live status, changed files and Main's review verdict, and code written by one model family can be reviewed by another family before commit.
  • Scheduled maintenance: Ordinary sessions do not repair the project in the background on their own. An optional scheduled nightly session works in a separate git worktree, reviews open issues and evidence-backed improvements, and uses recovery procedures seen in at least two sessions as material for skills. It leaves a morning summary and publishes changes as a release without installing them or restarting any PC's server. On PCs configured for scheduled sync, a morning session installs new releases that have passed public CI.
  • Plugins you can switch on and off — A plugin is a folder with a manifest and optional tools, extensions and sandboxed side panels, installed alongside the profile. Agents write new plugins directly to the repository and release them after checks and review. Right-deck plugin toggles apply to new sessions or through /reload while idle, which restarts the session rather than the server. The separate omp plugins in Settings behave differently: disabling an already-loaded plugin requires a CUELO runtime restart; /reload does not unload it.

Two parts in one repository

The workspace

Web app · repository root

Sessions and models

  • Find and continue past omp sessions per project, with live streaming of tool calls, cost and context use.
  • Branch from an earlier message or fork into a separate session. New sessions use a separate Git worktree when the repository is already in use.
  • Assign models to roles (default, smol, slow, plan, task …) using the same config.yml as the TUI.

Tools

  • Manage providers, models.yml, plugins and skills; preview files; switch Git worktrees.
  • Install and update external skills from public GitHub repositories with a static SkillSpector check. Warnings or an unavailable scanner require confirmation before installation.
  • A local maintenance board compares the last 7 days with the 7 days before for bottlenecks, cost and repeated corrections, and shows tool errors associated with opening a skill without claiming causation.

Voice and access

  • Call the agent by voice, or use a ChatGPT account for face-to-face interpreting between Korean and English, Chinese, Vietnamese, Japanese or Thai.
  • Password lock, browser notifications and PWA install. The interface is Korean-first, with English available.

The harness

Public rules · Tools/OMP_Global_Config/agent

  • How CUELO's agents work: a Main role that owns requirements, review and final judgement, and Maker roles that implement and verify delegated slices.
  • Dispatch and review contracts, a task guard, a routing advisor (Jev) and a command guard, as rules, SOPs and extensions.
  • Patches for the omp core.
  • node install.mjs setup copies it into your ~/.omp/agent, adding only missing files. You set your own modelRoles in config.yml. The web app works without it.

Install and run from source

CUELO is developed and verified on Linux. Native Windows server installation is unsupported, with no Windows CI or Windows release binaries. Public CI runs app and harness checks on Linux alongside a native reader build matrix; this does not guarantee support across all Linux distributions or on macOS. You need Node.js 22.19.0 or newer, Bun 1.4.4 or newer and Git for a source installation.

git clone https://github.com/gim47656-ship-it/CUELO.git
cd CUELO
node install.mjs setup     # install, build, patch the SDK, copy the public harness
node install.mjs start     # app + usage, btw, subagent in the foreground

# in another terminal
node install.mjs health    # checks that all four services answer

Then open http://127.0.0.1:30141 yourself; the browser does not open automatically. Sign in to the providers you want to use under Settings › Models & accounts with browser OAuth or an API key. If the official omp CLI (@oh-my-pi/pi-coding-agent) is already installed, omp login works too; these steps do not install it. Services listen on 127.0.0.1 by default; an explicit --hostname option can widen the web listener. Ctrl+C stops all four. health only checks that each service answers; it does not sign in or call a model provider.

setup copies the public harness into ~/.omp/agent but only adds missing files; it never changes or deletes existing ones, including config.yml. When no config.yml exists, it creates one with default operating settings (for example, automatic continuation and automatic memory retention stay off). These defaults ship with the installer and contain no one's personal configuration. For a new profile, choose your models with --model/--role during setup. For an existing profile, those flags leave its configuration unchanged; choose roles under Settings › Models & accounts.

CUELO runs agents with broad permissions: do not expose plain HTTP to the internet — put it behind a trusted HTTPS reverse proxy or a VPN. The full guide, including other port sets and troubleshooting, is in docs/installation.md (Korean).

To use the prepared npm build, run npm install -g cuelo, then cuelo setup and cuelo start. Check the services with cuelo health. The omp-web package is the upstream project, not CUELO. Releases are listed on GitHub Releases; container use is covered in docs/docker.md.

For agent-assisted installation and operation, see docs/agent-guide.md.
