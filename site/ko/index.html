CUELO omp 터미널 세션을 브라우저에서 이어 가고 다시 돌아오기

omp (oh-my-pi) CLI와 브라우저 사이에서 기록, 계정, 모델 설정이 그대로 공유됩니다. 작업 중 겪은 실수와 막힘을 기억, 규칙, 절차로 남겨 다음 작업에 반영하는 것도 목표로 합니다.

GitHub에서 소스 보기 소스에서 실행하기

Linux에서 로컬로 실행합니다. GitHub 소스 또는 npm의 cuelo 패키지로 설치하며 Node.js와 Bun이 필요합니다.

CUELO의 목적

  1. 실제로 일어난 일을 기록

    관측한 실패와 막힘을 있는 그대로 남깁니다.

  2. 원인인 부분만 수정

    기억·규칙·절차 가운데 원인이 된 곳만 바꿉니다.

  3. 다음 작업에 반영

    다음 작업이 그 변경을 알고 시작합니다.

  4. 재발했는지 확인

    문제가 다시 나오지 않아야 개선으로 봅니다. 다시 나오면 1단계로 돌아갑니다.

기록을 저장했다는 이유만으로 개선이 끝났다고 보지 않습니다. 이 흐름은 프로젝트가 지향하는 목표이며, 측정된 성과를 뜻하지 않습니다.

CUELO의 작업 방식

CUELO는 omp(oh-my-pi)용 웹 UI이자, 일을 나누어 맡기고 그 과정을 들여다볼 수 있는 멀티 에이전트 하네스입니다. 따로 떨어진 대화 앱으로 바꾸지 않고 쓰던 터미널 작업 흐름을 그대로 이어 갑니다.

  • CLI와 같은 세션 — CUELO는 로컬 웹 서버 안에서 omp SDK를 직접 실행하고, 터미널 CLI와 같은 ~/.omp/agent 세션·계정·모델 설정을 씁니다. CLI 화면 출력을 긁어 오는 방식이 아니어서 터미널에서 시작한 세션을 브라우저에서 이어 가고 다시 터미널로 돌아갈 수 있습니다.
  • 들여다볼 수 있는 위임 — Main 에이전트가 요구사항과 최종 판단을 맡고 세부 작업을 Maker 에이전트에게 나누어 맡기며, 가드가 배정된 파일 경계를 확인합니다. 맡긴 작업마다 실시간 상태, 바뀐 파일, Main의 검수 판정이 카드로 보이고, 한 모델 계열이 쓴 코드를 커밋 전에 다른 계열 모델이 검토하게 할 수 있습니다.
  • 예약 보수: 일반 세션은 백그라운드에서 프로젝트를 스스로 고치지 않습니다. 선택적으로 예약하는 야간 세션은 별도 git worktree에서 열린 이슈와 근거 있는 개선을 검토하고, 두 세션 이상에서 확인한 복구 절차를 스킬 작성 재료로 씁니다. 아침 요약을 남기고 변경을 릴리스로 게시하되 어떤 PC에도 설치하거나 서버를 재시작하지 않습니다. 예약 동기화가 설정된 PC에서는 아침 세션이 공개 CI를 통과한 새 릴리스를 설치합니다.
  • 켜고 끄는 플러그인 — 플러그인은 매니페스트와 선택 항목인 도구, 확장, 샌드박스 사이드 패널을 묶은 폴더로 프로필과 함께 설치됩니다. 에이전트는 새 플러그인을 저장소에 바로 쓰고 검사와 검토를 거쳐 릴리스합니다. 오른쪽 덱에서 바꾼 상태는 새 세션이나 유휴 상태의 /reload부터 적용됩니다. 이때 서버가 아니라 세션을 다시 시작합니다. 설정에서 관리하는 별도의 omp 플러그인은 다릅니다. 이미 불러온 플러그인을 끄려면 CUELO 런타임을 재시작해야 하며 /reload로는 해제되지 않습니다.

한 저장소의 두 부분

작업 공간

웹 앱 · 저장소 루트

세션과 모델

  • 프로젝트별로 지난 omp 세션을 찾아 이어 가고, 실시간 대화에서 도구 호출과 비용, 컨텍스트 사용량을 봅니다.
  • 이전 메시지에서 갈래를 나누거나 별도 세션으로 fork합니다. 저장소가 이미 사용 중이면 새 세션은 별도 Git worktree에서 시작합니다.
  • 역할(default, smol, slow, plan, task 등)별 모델을 TUI와 같은 config.yml로 지정하고 전환합니다.

도구

  • provider와 models.yml, 플러그인, 스킬을 관리하고, 파일을 미리 보거나 Git worktree를 전환합니다.
  • 공개 GitHub 저장소의 외부 스킬을 설치하거나 업데이트할 때 SkillSpector로 정적 검사를 합니다. 경고가 있거나 검사기가 없으면 설치 전에 확인을 받습니다.
  • 로컬 보수 점검판이 최근 7일과 직전 7일을 비교해 병목, 비용, 반복된 사용자 지적을 보여 주며, 스킬을 연 뒤의 도구 오류도 함께 표시하되 스킬이 원인이라고 단정하지 않습니다.

음성과 접근

  • 에이전트와 음성으로 통화하거나 ChatGPT 계정으로 한국어와 영어, 중국어, 베트남어, 일본어, 태국어 사이를 대면 통역합니다.
  • 비밀번호 잠금, 브라우저 알림, PWA 설치를 지원합니다. 한국어가 기본이고 영어도 고를 수 있습니다.

하네스

공개 규칙 · Tools/OMP_Global_Config/agent

  • CUELO가 쓰는 작업 방식입니다. Main은 요구·검수·최종 판정을, Maker는 위임받은 조각의 구현과 검증을 맡습니다.
  • 발주·검수 계약, task guard, 판단 라우팅(Jev), 명령 가드를 규칙·SOP·확장으로 제공합니다.
  • omp core용 패치.
  • node install.mjs setup이 자기 ~/.omp/agent에 없는 파일만 복사합니다. 역할별 모델(modelRoles)은 자기 config.yml에 지정합니다. 웹 앱은 하네스 없이도 동작합니다.

하네스 문서 읽기

이 저장소로 되는 것과 따로 필요한 것

구분내용
이 저장소만으로 동작웹 앱 전체: 세션 탐색·실시간 대화·분기/fork, 모델 역할, provider·플러그인·스킬 관리, 파일 미리보기, worktree, 비밀번호 잠금, 캐릭터 알림, 효율 패널(~/.omp/stats.db 읽기).

별도 로컬 서비스계정 사용량 카드, 사이드 챗(/btw), SubAgent 아카이브는 로컬 서비스 세 개(usage, btw, subagent)에서 데이터를 받습니다. node install.mjs start가 앱과 함께 127.0.0.1에 띄웁니다. 사이드카 기록은 자기 PC에 남습니다. 서비스가 떠 있지 않으면 해당 패널만 「연결 안 됨」으로 표시됩니다.
OMP 하네스 (공개)Tools/OMP_Global_Config의 규칙·SOP·확장과 omp core 패치. 위 설명 참고.
포함하지 않는 것로그인 정보·API 키, 어떤 provider·계정·모델을 쓰는지 정한 개인 설정(config.yml·models.yml), 개인 skill, 작업 기록, 관리자 개인 PC의 배포 도구.

소스에서 설치하고 실행하기

CUELO의 개발과 검증 환경은 Linux입니다. 네이티브 Windows 서버 설치는 지원하지 않으며 Windows CI와 Windows 릴리스 바이너리를 제공하지 않습니다. 공개 CI는 Linux에서 앱과 하네스를 검사하고 네이티브 리더를 플랫폼별로 빌드합니다. 모든 Linux 배포판의 지원이나 macOS 동작과 지원을 보장하지는 않습니다. Node.js 22.19.0 이상, Bun 1.4.4 이상이 필요하며, 소스 설치에는 Git도 필요합니다.

git clone https://github.com/gim47656-ship-it/CUELO.git
cd CUELO
node install.mjs setup     # 설치·빌드·SDK 패치·공개 하네스 복사
node install.mjs start     # 앱 + usage·btw·subagent를 포그라운드로 실행

# 다른 터미널에서
node install.mjs health    # 네 서비스가 응답하는지 확인

그다음 http://127.0.0.1:30141을 직접 엽니다. 브라우저는 자동으로 열리지 않습니다. 설정의 「모델·계정」 화면에서 쓸 provider의 로그인 버튼을 눌러 브라우저 OAuth나 API 키로 직접 로그인합니다. 공식 omp CLI(@oh-my-pi/pi-coding-agent)를 이미 설치해 두었다면 omp login을 써도 됩니다. 이 절차에서는 CLI를 따로 설치하지 않습니다. 기본 설정에서는 127.0.0.1에서 열리며, 웹 접속 범위는 --hostname 옵션을 직접 지정해 넓힐 수 있습니다. Ctrl+C를 누르면 네 개가 함께 종료됩니다. health는 각 서비스가 응답하는지만 확인하며, 로그인하거나 모델 provider를 호출하지 않습니다.

setup은 공개 하네스를 ~/.omp/agent에 복사하되 없는 파일만 추가하고, config.yml을 포함해 이미 있는 파일은 바꾸거나 지우지 않습니다. config.yml이 없을 때만 기본 운영 설정으로 새로 만듭니다(예: 자동 이어 가기와 기억 자동 저장은 꺼 둠). 이 기본값은 설치 스크립트에 들어 있으며 누군가의 개인 설정을 복사한 것이 아닙니다. 새 프로필에서는 setup의 --model/--role로 사용할 모델을 직접 지정합니다. 기존 프로필에는 이 옵션을 줘도 설정이 바뀌지 않으며, 설정의 「모델·계정」 화면에서 역할별로 고릅니다.

CUELO는 권한이 큰 에이전트를 실행하므로, 평문 HTTP를 인터넷에 열지 말고 신뢰할 수 있는 HTTPS 리버스 프록시나 VPN 뒤에 두세요. 다른 포트 세트와 문제 해결을 포함한 전체 안내는 docs/installation.md에 있습니다.

빌드된 npm 패키지는 npm install -g cuelo 뒤 cuelo setup, cuelo start로 실행하고 cuelo health로 확인합니다. npm의 omp-web은 upstream 프로젝트이며 CUELO와 별개입니다. 릴리스는 GitHub Releases에, 컨테이너 실행은 docs/docker.md에 있습니다.

에이전트용 설치·운영 안내는 docs/agent-guide.md에 있습니다.
