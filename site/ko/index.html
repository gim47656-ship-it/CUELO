CUELO omp(oh-my-pi)를 위한 AI 코딩 에이전트 작업 공간과 하네스

CUELO는 omp SDK를 로컬 웹 서버 안에서 그대로 실행하고, omp CLI와 같은 ~/.omp/agent 디렉터리를 씁니다. 터미널에서 하던 세션을 브라우저에서 이어 가고, 다시 터미널로 돌아가도 기록·계정·모델 설정이 하나로 유지됩니다.

GitHub에서 소스 보기 소스에서 실행하기

GitHub 소스 또는 npm의 cuelo 패키지로 설치합니다. Node.js와 Bun이 필요합니다.

CUELO의 목적

작업 중 확인한 실패와 막힘을 기억·작업 규칙·실행 절차에 반영해, 사람이 같은 문제를 다시 지적하지 않아도 다음 작업에서 실수를 줄이는 것입니다.

  1. 실제로 일어난 일을 기록

    관측한 실패와 막힘을 있는 그대로 남깁니다.

  2. 원인인 부분만 수정

    기억·규칙·절차 가운데 원인이 된 곳만 바꿉니다.

  3. 다음 작업에 반영

    다음 작업이 그 변경을 알고 시작합니다.

  4. 재발했는지 확인

    문제가 다시 나오지 않아야 개선으로 봅니다. 다시 나오면 1단계로 돌아갑니다.

기록을 저장했다는 이유만으로 개선이 끝났다고 보지 않습니다. 이 흐름은 프로젝트가 지향하는 목표이며, 측정된 성과를 뜻하지 않습니다.

한 저장소의 두 부분

작업 공간

웹 앱 · 저장소 루트

  • 프로젝트별로 지난 omp 세션을 찾아 이어 가고, 실시간 대화에서 도구 호출·비용·컨텍스트 사용량을 봅니다.
  • 이전 메시지에서 갈래를 나누거나 별도 세션으로 fork합니다.
  • 역할(default, smol, slow, plan, task 등)별 모델을 TUI와 같은 config.yml로 지정·전환합니다.
  • provider·models.yml·플러그인·스킬 관리, 파일 미리보기, Git worktree 전환.
  • 비밀번호 잠금, 브라우저 알림, PWA 설치. 한국어가 기본이고 영어·중국어 간체도 고를 수 있습니다.

하네스

공개 규칙 · Tools/OMP_Global_Config/agent

  • CUELO가 쓰는 작업 방식입니다. Main은 요구·검수·최종 판정을, Maker는 위임받은 조각의 구현과 검증을 맡습니다.
  • 발주·검수 계약, task guard, 판단 라우팅(Jev), 명령 가드를 규칙·SOP·확장으로 제공합니다.
  • omp core용 패치.
  • node install.mjs setup이 자기 ~/.omp/agent에 없는 파일만 복사합니다. 역할별 모델(modelRoles)은 자기 config.yml에 지정합니다. 웹 앱은 하네스 없이도 동작합니다.

하네스 문서 읽기

이 저장소로 되는 것과 따로 필요한 것

구분내용
이 저장소만으로 동작웹 앱 전체: 세션 탐색·실시간 대화·분기/fork, 모델 역할, provider·플러그인·스킬 관리, 파일 미리보기, worktree, 비밀번호 잠금, 캐릭터 알림, 효율 패널(~/.omp/stats.db 읽기).
provider 로그인이 필요함세션·인증·모델 설정은 omp CLI와 같이 쓰는 프로필 ~/.omp/agent에 있습니다. provider 로그인은 사용자가 CUELO의 설정 › Models에서 직접 합니다.
별도 로컬 서비스계정 사용량 카드, 사이드 챗(/btw), SubAgent 아카이브는 로컬 서비스 세 개(usage, btw, subagent)에서 데이터를 받습니다. node install.mjs start가 앱과 함께 127.0.0.1에 띄웁니다. 자격 증명과 기록은 자기 PC에 남습니다. 서비스가 떠 있지 않으면 해당 패널만 「연결 안 됨」으로 표시됩니다.
OMP 하네스 (공개)Tools/OMP_Global_Config의 규칙·SOP·확장과 omp core 패치. 위 설명 참고.
포함하지 않는 것로그인 정보·API 키, 어떤 provider·계정·모델을 쓰는지 정한 개인 설정(config.yml·models.yml), 개인 skill, 작업 기록, 관리자 개인 PC의 배포 도구.

소스에서 설치하고 실행하기

CUELO의 개발·검증 환경은 Windows입니다. macOS·Linux는 개발·테스트 환경이 아니므로 동작과 지원을 보장하지 않습니다. Node.js 22.19.0 이상, Bun 1.4.2 이상이 필요하며, 소스 설치에는 Git도 필요합니다.

git clone https://github.com/gim47656-ship-it/CUELO.git
cd CUELO
node install.mjs setup     # 설치·빌드·SDK 패치·공개 하네스 복사
node install.mjs start     # 앱 + usage·btw·subagent를 포그라운드로 실행

# 다른 터미널에서
node install.mjs health    # 네 서비스가 응답하는지 확인

그다음 http://127.0.0.1:30141을 직접 엽니다. 브라우저는 자동으로 열리지 않습니다. 설정 › Models에서 쓸 provider의 로그인 버튼을 눌러 브라우저 OAuth나 API 키로 직접 로그인합니다. 공식 omp CLI(@oh-my-pi/pi-coding-agent)를 이미 설치해 두었다면 omp login을 써도 됩니다. 이 안내는 CLI를 따로 설치하지 않습니다. 모든 서비스는 127.0.0.1에서만 열리고, Ctrl+C를 누르면 네 개가 함께 종료됩니다. health는 각 서비스가 응답하는지만 확인하며, 로그인하거나 모델 provider를 호출하지 않습니다.

setup은 공개 하네스를 ~/.omp/agent에 복사하되 없는 파일만 추가합니다. 이미 있는 파일은 바꾸거나 지우지 않습니다. config.yml이 없을 때만 안전한 기본 운영 설정으로 새로 만듭니다(예: provider를 스스로 호출하는 자동 기능은 꺼 둠). 이 기본값은 설치 스크립트에 들어 있는 것이며 누군가의 개인 설정을 복사하지 않습니다. 이미 있는 config.yml은 그대로 둡니다. 사용할 모델 선택도 사용자가 합니다. setup의 --model/--role로 지정하거나 나중에 설정 › Model roles에서 고릅니다. 설치 스크립트가 모델을 추측해 채우지 않습니다.

CUELO는 권한이 큰 에이전트를 실행하므로, 평문 HTTP를 인터넷에 열지 말고 신뢰할 수 있는 HTTPS 리버스 프록시나 VPN 뒤에 두세요. 다른 포트 세트와 문제 해결을 포함한 전체 안내는 docs/installation.md에 있습니다.

빌드된 npm 패키지는 npm install -g cuelo 뒤 cuelo setup, cuelo start로 실행하고 cuelo health로 확인합니다. npm의 omp-web은 upstream 프로젝트이며 CUELO와 별개입니다. 릴리스는 GitHub Releases에, 컨테이너 실행은 docs/docker.md에 있습니다.

하네스 비교

CUELO 관리자가 따로 게시한 페이지에서 같은 AI 모델·같은 코딩 과제로 도구(CUELO, Claude Code, Codex)만 바꿔 비교한 결과를 볼 수 있습니다. 측정 조건과 주의 사항, 약한 부분도 그 페이지에 적혀 있습니다.
