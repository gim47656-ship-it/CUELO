# 웹·발표·문서 제작 도구 선택

## 적용

- 사용자가 웹 화면, HTML 발표·보고자료, 편집 가능한 PPT, Word 문서, PDF 보고서의 제작·수정을 요청하면 Main과 Maker 모두 이 규칙을 읽는다. 도구 이름을 사용자가 말할 때까지 기다리지 않는다. 관련 없는 코드·조사 작업에는 적용하지 않는다.
- 먼저 요청한 산출물, 기존 원본·템플릿, 대상 독자와 쓰는 방식을 확인하고 아래에서 맞는 경로만 고른다. 문맥에서 정해진 조건은 다시 묻지 않는다. 사용자의 형식·브랜드·기존 디자인 시스템이 우선이다.
- 관련 스킬은 직접 읽고 현재 설치된 도구의 지원 형식과 실행 경로를 확인한다. 다른 PC의 설치 기록이나 예제 성공을 이 환경의 실행 증거로 쓰지 않는다. 없는 도구를 설치된 것처럼 쓰지 않는다.
- 기존 도구·템플릿·오픈소스 부품을 먼저 검토하되 이번 결과에 필요 없는 패키지·프레임워크를 추가하지 않는다. 필요한 도구가 없으면 기존 승인 경계 안에서 준비하거나 필요한 승인만 요청한다. MCP 등록·인증·권한·비용·외부 게시 승인은 별개다.

## 산출물별 경로

| 산출물 | 먼저 참고할 것 | 제작과 확인 |
|---|---|---|
| 웹 UI | `rule://frontend`; shadcn, Magic UI, HyperUI의 해당 부품 원본과 예제 | 기존 디자인 시스템을 유지하고 필요한 부품만 맞춰 쓴다. 실제 화면에서 데스크톱·모바일, 키보드 이동·초점, 모션 축소를 확인한다. |
| HTML 발표·보고 슬라이드 | `skill://frontend-slides`, `rule://frontend`; 편집형 PPT와 공유하는 발표·보고 원칙 | 웹페이지가 아니라 보고자료로 구성한다. 아래 발표 기준과 키보드 넘김, 오프라인 열기, PDF 출력을 확인한다. |
| 편집 가능한 PPTX | `skill://presentation-skill`; 기존 PPTX·원본 소스·재사용 가능한 템플릿 | 원본을 보존한다. 소스가 있으면 소스에서 고치고, 실제 텍스트·표·차트 편집 가능 여부와 노트·마스터·한글 배치를 확인한다. 통이미지 슬라이드를 편집형 PPT로 대신하지 않는다. |
| Markdown에서 Word·PPTX 변환 | Pandoc 공식 매뉴얼; `skill://office-document-editing` | 기존 `reference.docx`·`reference.pptx`가 있으면 `--reference-doc`로 스타일을 이어 쓴다. 표·한글 스타일·노트·마스터 중 바뀌는 범위를 구조와 렌더 결과로 확인한다. |
| 수식·표·목차가 있는 PDF 보고서 | Typst 공식 문서; `skill://korean-report-writing` | 로컬 글꼴·에셋으로 컴파일한다. 한글 텍스트 추출, 글꼴 임베딩, 표·수식·목차·페이지 배치를 확인한다. PPTX가 필요한 요청을 PDF로 바꾸지 않는다. |
| 기존 슬라이드 검사·사본 비교 | `skill://office-document-tooling`; 설치된 DeckCraft CLI의 도움말 | 읽기·렌더와 다시 저장하기를 구분한다. 해당 버전·형식의 무변경 저장 및 한 곳 수정 시험을 사본에서 통과해야 저장에 쓴다. 구조 보존과 렌더 판정은 별개이며 실패한 경로를 기본 편집기로 삼지 않는다. |

DeckCraft 0.8.0 사본 시험에서는 변경 없는 저장도 노트 쪽번호 자리표시자와 일부 마스터 설정을 누락했고, 자체 렌더에서 한글 굵기와 혼합 문장의 글자 크기가 달라졌다. 읽기·구조 확인에 활용하되 원본 덮어쓰기와 한글 글꼴의 최종 시각 판정에는 쓰지 않는다. 다른 버전에서도 보존·렌더 결과를 별도로 확인한다.

## PPT와 HTML 보고 슬라이드의 공통 기준

- 발표용인지 배포해 읽는 자료인지 문맥으로 판단한다. 보고자료라면 제목에 판단이나 내용을 드러내고, 각 장에 그 판단의 근거를 둔다. 자료가 부족하면 빈 측정값·고객·성과를 만들어 채우지 않는다.
- 한 장의 중심 메시지를 정하고 필요한 표·도표·이미지·설명을 그에 맞춰 배치한다. 모든 장을 같은 카드나 좌우 두 칸으로 반복하지 않는다. 글자가 작아지거나 내용이 잘리면 장을 나누고, 임의 요약으로 근거를 없애지 않는다.
- HTML 발표 화면은 16:9 고정 스테이지를 비례 축소한다. 휴대폰에서도 슬라이드 내용을 웹페이지처럼 재배치하지 않는다. 읽기용 문서가 별도로 필요하면 요청 범위 안에서 구분해 만든다. `1920×1080`·`1280×720`과 휴대폰에서 넘침·겹침·가독성을 확인한다.
- 방향키·Space·PageUp/PageDown·Home/End를 확인하고, 발표자 노트는 발표 화면과 인쇄 본문에서 분리한다. 애니메이션은 내용을 가리지 않아야 하며 모션 축소 설정을 따른다.
- HTML은 글꼴·스크립트·스타일을 로컬에 두어 열람 중 CDN에 의존하지 않는다. PDF 출력은 실행 환경의 브라우저 경로를 따른다. ego lite가 있으면 TaskSpace의 `Page.printToPDF`를 쓰고, 슬라이드 수와 PDF 페이지 수·16:9 크기·페이지별 텍스트를 대조한 뒤 렌더를 본다.

## 출처·작성·전달

- 오픈소스는 표준 라이선스, 출처 고지, 포함 에셋 조건을 확인한다. 필요한 LICENSE·저작권 고지를 보존한다. 명시적 라이선스가 없거나 에셋 조건이 모호한 부분만 보류하고 불필요한 법률 감사로 넓히지 않는다.
- 부품 소스와 템플릿을 참고하는 일은 전체 도구·디자인 시스템 교체를 뜻하지 않는다. shadcn MCP가 이미 연결돼 있으면 검색·예제 조회에 쓰며, 없으면 공식 레지스트리나 소스를 읽는다. 연결돼 있지 않은 MCP를 자동 등록하지 않는다.
- 모든 새 본문·슬라이드 문구·표 설명·화면 문구는 기존 `draft` 규칙을 따른다. 실행 도구 선택이 초안·문체 점검·`slop_check`를 대체하지 않는다. 모델 역할과 폴백은 별도 승인 없이 바꾸지 않는다.
- 기존 Office 문서 편집은 LibreOffice 기본 규칙을 유지한다. 원본을 덮어쓰지 않고 사본이나 새 파일로 작업한다. 프로그램 종료 코드와 파일 생성만으로 완료라고 하지 말고 실제 산출물의 내용·편집 가능성·렌더를 확인한다.
- 최종 파일과 재사용할 소스·템플릿·필요한 출처를 함께 남기고, 실제 실행 명령과 검증된 범위를 작업 기록에 적는다. 확인하지 못한 기능은 확인했다고 쓰지 않는다.
