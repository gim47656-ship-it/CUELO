# 프로젝트 문서 지도와 기록

소스·설정·데이터를 실제로 바꾼 작업은 프로젝트 루트의 기존 `HANDOFF.md`를 갱신해 변경과 함께 commit/push한다. 질문·읽기 전용 조회만 한 세션에는 쓰지 않는다. 프로젝트마다 같은 역할 분담을 적용한다.

| 문서 | 담는 것 | 담지 않는 것 |
|---|---|---|
| `HANDOFF.md` | 지금 유효한 상태, 다음 행동, 남은 경계 | 끝난 작업의 서사, 검증 로그, 설정값 사본, 다른 문서가 정본인 사실의 사본 |
| `README.md` | 설치·운영·복구 절차 | 현재 상태, 값을 복사한 설정 |
| `doc/README.md` | 문서 지도와 읽기·갱신 규칙 | 상태 서술 |
| `doc/history/YYYY/MM/DD-주제/` | 그 작업의 판단과 실행 기록 | 현재 상태 |

- 새 세션은 `HANDOFF.md`를 먼저 읽고, 다음으로 `doc/README.md`에서 이번 작업에 필요한 문서만 고른다. 문서와 실제 저장소 상태가 다르면 저장소를 우선하며 문서는 UTF-8로 유지한다. **`HANDOFF.md` 편집은 Main이 한다.** Maker는 자기 `doc/history` 기록만 쓰고 현재 상태에 반영할 내용은 종료 보고로 넘긴다. 다른 문서는 해당 변경 owner가 갱신하며, 문서 전담 발주·인계·패킷은 만들지 않는다.
- **한 사실은 한 곳에서만 서술한다.** 같은 상태를 여러 문서나 저장소에서 독립적으로 반복하지 않는다. 전역 기능의 조건은 전역 문서가 정본이며 하위 프로젝트는 그 절을 참조하고 고유 차이만 적는다. 계속 적용되는 발동 조건·운영 제약·알려진 함정은 운영 문서의 고정 절에 두고, history에는 그 사실을 바꾼 판단과 실행만 기록한다.
- 상태 보고에서 계측 가능성·실제 측정·개선 입증을 구분한다. 관측 경로의 존재만으로 `미입증`을 바꾸지 않는다.
- 작업 행은 다음 담당자의 행동이나 미해결 경계가 남았는지로 판정한다. 합의한 완료 조건을 채우고 둘 다 없으면 Main이 작업을 종결하는 마감에 제거한다. 적용 후 관측만 남았으면 관측 행동과 종료 조건만 남긴다. 시간·파일 크기는 삭제 기준이 아니다.
- 다음 신호를 보면 해당 절을 바로 고친다: ① Maker가 끝낸 범위가 HANDOFF에서 미적용으로 남음 ② 작업 행의 다음 행동·미해결 경계를 설명할 수 없음 ③ 같은 상태를 둘 이상 독립 서술함 ④ 열린 일이 늘지 않는데 HANDOFF만 늘어남. Maker는 종료 보고에 HANDOFF 영향 주제와 남은 행동 유무를 적는다. Main은 관련 절과 참조처만 확인하며 상시 감사·별도 hook·문서 DB를 만들지 않는다.
- 기록은 역할별이다: `DD-주제/main.md`는 Main 판단·수용·공유 인계, `maker-<name>.md`는 그 Maker의 변경·검증·남은 제한이다. Maker는 자기 기록만 쓰며 Main 단독 작업에는 Maker 기록을 만들지 않는다. 발주 시 Main은 Maker 기록과 `evidence/` 경로를 `OWNED_PATHS`에 넣고, 공유 지도는 Main 또는 지정된 한 owner가 갱신한다. 긴 diff·로그는 작업 폴더 `evidence/`에 두고 상대 링크로 가리킨다. secret·대화 원문·인증 DB는 기록하지 않는다.
- 검색 순서는 ① `HANDOFF.md` ② `doc/README.md` 지도·월별 목록 ③ 경로·주제 키워드로 `doc/history/**/*.md`의 `RECORD:` 헤더(`SCOPE`·`PATHS`)를 최신순 검색 ④ 일치 기록의 헤더와 필요한 줄 범위만 읽는다. `STATUS: superseded-by <path>`면 새 경로로 이동한다. 목차·헤더로 못 찾았을 때만 헤더 없는 기존 기록의 본문을 제한 검색한다. 기존 기록에 헤더를 일괄 추가하지 않는다. Main은 찾은 locator를 브리프에 넣어 재검색을 막는다. 후보가 넷 이상이고 헤더로 가릴 수 없을 때만 judge를 쓸 수 있으며 상시 색인·judge·Wiki·기억 계층은 두지 않는다.
- 검색 헤더는 제목 바로 뒤에 둔다:

  ```text
  RECORD:
  DATE: YYYY-MM-DD
  SCOPE: <주제 키워드>
  PATHS: <대상 경로>
  STATUS: accepted | pending-user-device-check | partial | superseded-by <path>
  ```

  헤더는 검색 키일 뿐 판단·근거·검증·남은 경계를 대신하지 않는다. 기존 기록에 헤더를 붙이는 것은 그 기록을 다시 여는 경우만 허용한다.
- 프로젝트에 `doc/` 같은 별도 문서 루트가 있으면 그 루트와 지도를 따른다. 개편 전 원문 스냅샷은 작업 기록과 섞지 않고 `DD-주제.md` 한 파일로 보존하며 기존 링크를 깨는 이동·이름 변경은 하지 않는다.
- 내용 없는 틀·빈 폴더·CURRENT 중복본을 만들지 않는다. 계속 유효한 지식은 현행 문서에 반영하고 history에만 묻지 않는다. 다른 PC의 로그·임시 경로·`history://` 증거는 그 제한과 revision·관측 요약·재확인 방법을 기록한다. 다른 프로젝트는 그 프로젝트의 기존 문서 구조를 따른다.
