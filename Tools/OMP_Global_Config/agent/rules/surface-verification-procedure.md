description: 브라우저·화면 검증, 이미지 확인, 문서·로그 분류나 긴 작업 감시 전에 읽는다.

- **브라우저 경로는 실행 환경 지침이 정한다.** ego lite TaskSpace(`ego_browser`)를 쓸 수 있는 PC에서는 그것이
  기본이고 CUELO 화면 검증은 검증 프로필(`profile: "verify"`)에서 한다. 그 밖의 PC에서 화면 검증은
  `browser.open`에 `app: { relay: false }`를 준 headless로 한다. 이를 빼면 relay가 기본이라 **사용자의 실제
  브라우저**에 탭이 열린다. relay 탭을 닫을 때는 `browser.close({ name })`로 자기 탭만
  닫고 `all`·`kill`·`app.path`는 쓰지 않는다 — 사용자 창까지 닫히거나 기존 프로세스에 붙는다.
  빌드가 깨진 화면을 사용자에게 띄우지 않는다. HTML·웹 페이지를 PDF로 인쇄하는 것도 브라우저 작업이라 같은 경로를
  따른다: ego lite PC에서는 TaskSpace에서 `page.cdp("Page.printToPDF")`로 받고, Edge·Chrome `--print-to-pdf`를 따로
  띄우지 않는다(2026-10-26 사용자 지적). 이미지·문서 확인은 `read`의 `경로?q=<질문>`으로
  먼저 해결하고, 실제 DOM 렌더가 필요할 때만 브라우저를 연다. 글자·숫자·표 전사는 `경로?ocr=<질문>`(OCR 전용
  `ocr` 역할 모델)으로, 특정 문구·값 확인과 레이아웃·간격·색·정렬·잘림·좌표 판단은 `?q=`(`vision` 역할 모델)로
  먼저 묻는다. `?q=`·`?ocr=` 없는 이미지 read는 그 경로로 한 번 묻기 전까지 계속 막힌다. 그 답으로 판단할 수
  없을 때만 같은 경로를 다시 읽어 직접 본다.
- **화면 확인은 모델 턴을 줄이는 순서로 한다(Main·Maker 공통).** 웹은 `browser`, 네이티브 데스크톱
  창(WinForms·WPF·VB6 등)은 `computer`를 쓰고, 로직·API는 테스트와 실제 실행으로 확인한다. 조작·대기·
  확인 여러 단계를 한 `eval` 셀에 묶고, 확인은 DOM 텍스트·AX 트리의 문자열 비교를 먼저 쓴다. 문자열로
  가를 수 없는 판정("오류 대화상자가 떴나", "수용 조건과 맞나")만 같은 셀에서 `judge()`(JEV)에 텍스트로
  넘기고, 모양을 봐야 할 때만 스크린샷을 찍는다. `judge()` 결과는 참고 신호이며 최종 수용 근거가 아니다.
  `computer`는 사용자의 실제 데스크톱을 조작하므로 자기가 띄운 창만 다루고, 삭제·전송·결제처럼 되돌릴 수
  없는 버튼은 누르지 않는다. 여러 단계 데스크톱 조작도 Main이 `computer`로 직접 한다(2026-10-30 사용자 결정, 별도
  작업자에게 넘기던 `computer_task`는 느리고 자주 멈춰 없앴다). 결과가 중요하면 `windows_control list`·AX로 다시 읽어
  확인하고, 띄운 창은 PID를 확인해 자기 것만 닫는다. 이 규칙은 막는 게이트가 아니라 권고다.
  **테스트·검증은 사용자 화면 밖에서 돌린다(2026-10-26 사용자 결정).** 웹 테스트는 사용자 탭과 떨어진 독립
  공간(ego lite PC는 검증 프로필 TaskSpace, 그 밖은 headless)에서만 한다. 앱·Windows 프로그램 테스트는 사용자가
  보는 데스크톱에 창을 띄우지 않고 백그라운드에서 돌린다: 숨은 Windows 데스크톱(별도 desktop 객체), 화면 밖
  위치나 표시 없는 하네스, 장비 없는 로직 테스트 중 대상에 맞는 것을 쓴다. 이 방식으로 확인할 수 없는 항목(실제
  GPU·표시 장치가 필요한 렌더 등)은 미확인으로 남기고, 사용자 화면에 띄우는 건 사용자가 요청하거나 승인했을
  때만이다. 띄운 프로세스는 자기 PID로만 끝낸다.
  같은 순서를 **여러 문서·기록·로그를 분류할 때**와 **긴 작업을 감시할 때**도 쓴다. 헤더·정해진 문구로
  먼저 거르고, 남은 것이 넷 이상이면 `judge_batch`로 한 번에 나눈 뒤 애매한 것만 직접 읽는다. 배포·빌드·긴
  테스트는 셀 안 반복문에서 종료 문구를 문자열로 잡고, "멈췄나·진행 중인가"처럼 문구로 못 가르는 상태만
  `judge()`에 묻는다. 기준선과 비교하는 재측정은 기준선과 같은 방법으로 세고, JEV 분류는 그 방법이 못
  가른 나머지에만 보조로 쓴다.
