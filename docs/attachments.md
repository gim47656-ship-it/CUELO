# 파일 첨부와 음성 받아쓰기

입력창에 파일을 끌어 놓거나, 붙여넣거나, 파일 선택 버튼으로 첨부합니다. 작은 텍스트 문서는 본문으로 전달하고, 저장형 첨부는 원본을 서버에 보관한 뒤 파일 경로를 대화에 넣습니다. 라이브 음성 통화와 녹음 파일 받아쓰기는 별개 기능입니다.

## 파일 크기

**설정 → 첨부 파일**에서 저장형 첨부의 파일당 업로드 한도를 바꿉니다. 기본값은 **100MB**입니다. 서버는 업로드를 청크 단위로 저장하며, 제한을 넘거나 전송을 중단하면 완성되지 않은 업로드를 정리합니다.

이 한도는 파일 원본의 저장 한도입니다. 모델에 직접 넣는 이미지·문서 본문의 한도와는 다릅니다. 큰 파일을 저장했다고 전체 내용이 모델 컨텍스트에 한꺼번에 들어가는 것은 아닙니다.

## 음성 파일

음성 받아쓰기는 기존 ChatGPT/Codex OAuth 로그인으로만 처리합니다. 받아쓰기에는 비공개 비문서화 엔드포인트를 사용합니다. 모델 역할 `draft`와는 무관하며 별도 API 키나 Google 자격은 필요하지 않습니다. 사용량은 연결된 ChatGPT 계정의 조건을 따릅니다.

- 음성 파일을 첨부하면 크기와 관계없이 모든 파일의 길이를 이 PC에서 FFmpeg로 확인합니다. 이때는 아무것도 보내지 않습니다. 입력창에 길이와 15초 조각 기준으로 올림한 예상 받아쓰기 호출 횟수, 보내는 곳과 보관 안내를 표시하고 사용자의 선택을 기다립니다. 버튼은 「받아쓰기 시작」과 「받아쓰지 않기」입니다. 시작을 누르기 전에는 아무것도 보내지 않습니다.
- 「받아쓰기 시작」을 누르면 원본을 보존하고 전사용 사본을 15초 이하의 MP3 조각으로 나눕니다. 조각을 기존 ChatGPT/Codex 로그인으로 순서대로 보내고 결과를 연결합니다. 언어는 자동으로 감지합니다.
- 15초는 15초 클립 요청이 200으로 돌아온 시험 한 번을 근거로 정한 로컬 분할 기준입니다. 제공자의 공식 최대 한도는 아닙니다.
- 「받아쓰지 않기」를 누르면 아무것도 보내지 않고 전사문 없이 저장된 파일 경로만 첨부합니다.
- 받아쓰기 엔드포인트는 비공개 비문서화 상태이며 계정의 사용량 한도는 확인되지 않았습니다. 시험 응답에 `asset_ttl='30d'`가 있었지만 실제 보관 및 삭제 정책은 확인되지 않았습니다.
- 다른 제공자로 넘어가는 대체 전사는 제공하지 않습니다. 옛 화면에서 받은 대체 전사 요청(`fallbackToken`)은 409로 거부하고 아무것도 보내지 않습니다. 같은 첨부를 이미 받아쓰는 중이면 두 번째 요청도 409로 거부합니다.
- 진행 중 취소하거나 일부 조각이 실패하면 전체 전사가 완료된 것으로 표시하지 않습니다. 일부 결과는 붙이지 않고 전체 조각 중 처리한 조각 수를 알립니다. 임시 변환 폴더를 정리하고 원본을 보존하므로 오류를 확인한 뒤 「다시 시도」할 수 있습니다.

처리 시간은 파일의 길이와 형식 및 제공자 응답에 따라 달라집니다. 예상 호출 수는 금액이나 완료 시각을 보장하지 않습니다. 길이 확인과 조각 분할에는 원본 파일 크기와 관계없이 FFmpeg가 필요합니다. 의존성 설치 때 운영체제에 맞는 실행 파일을 내려받으므로 설치 중 네트워크와 디스크 공간이 필요합니다. 다운로드가 막히거나 실행 파일을 쓸 수 없으면 음성 도구를 쓸 수 없다는 오류를 안내하고 받아쓰기를 준비하지 못합니다. FFmpeg와 배포 패키지의 라이선스는 [ffmpeg-static](https://github.com/eugeneware/ffmpeg-static) 및 그 배포물을 확인하세요.

## 자동 정리

자동 정리는 기본으로 켜져 있으며 **설정 → 첨부 파일**에서 끌 수 있습니다. 서버 시작 약 1분 뒤 첫 검사를 하고, 실행 중 24시간마다 정리 대상을 확인합니다. 서버가 꺼져 있는 동안에는 삭제하지 않습니다.

삭제 기준은 업로드 날짜가 아닙니다. **어느 대화·분기·초안에서도 사용하지 않는 것으로 확인된 시점부터 7일**이 지난 파일만 다음 검사에서 삭제합니다.

- 대화 기록이나 초안이 참조하는 파일은 기간과 관계없이 보존합니다.
- 전송을 마쳤지만 대화 기록에 저장됐는지 아직 확인되지 않은 첨부도 보존합니다.
- 다른 대화로 fork한 파일은 원래 대화 하나를 삭제했다고 함께 삭제하지 않습니다.
- 업로드나 전사가 진행 중인 원본도 보호합니다.
- 다시 참조하면 미사용 유예 시간을 취소합니다.
- 참조 검사나 파일 정보 확인에 실패하면 삭제하지 않습니다.
- 이 기능 도입 전의 파일처럼 참조·관리 정보가 불확실한 원본은 자동 삭제 대상에서 제외합니다.

탭을 닫거나 한동안 접속하지 않았다는 이유만으로 초안을 버리지 않습니다. 사용 여부가 불확실한 파일이 남을 수 있지만, 자동 정리를 위해 과거 대화의 원본을 추측해서 삭제하지는 않습니다.
