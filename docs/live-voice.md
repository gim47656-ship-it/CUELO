# 라이브 통화와 캐릭터 음성

입력창의 마이크 버튼은 이 대화의 에이전트와 음성으로 통화합니다. 통화 모델은 Codex live이고, 혼자 답할 수 없는 일은 지금 세션에 위임한 뒤 그 답을 읽어 줍니다. 통화 전사는 세션 기록에 남고, 「통화 끊어」처럼 끝내는 말만 하면 통화가 끝납니다.

Cartesia API 키를 넣고 캐릭터 음성을 준비하면, 통화는 **지금 이 대화의 Main 캐릭터** 목소리로 말합니다. 키가 없으면 지금까지처럼 Codex 기본 음성으로 통화합니다.

## 준비

1. 마이크 버튼 옆 설정 버튼을 눌러 **캐릭터 통화 음성** 창을 엽니다.
2. Cartesia API 키(`sk_car_…`)를 붙여 넣고 **키 저장**을 누릅니다. 저장 전에 크레딧을 쓰지 않는 목록 조회 한 번으로 키를 확인하며, 틀린 키는 저장하지 않습니다.
3. 업로드·크레딧·권리 확인란을 읽고 체크한 뒤 **캐릭터 음성 준비**를 누릅니다.

준비는 이 버튼을 눌렀을 때만 실행됩니다. 서버 시작, 설정 창 열기, 통화 시작은 Cartesia에 복제 요청을 보내지 않습니다. 준비는 캐릭터마다 다음을 합니다.

- 번들 참조 음성(`public/audio/live/<id>-reference.wav`, 일본어)을 사용자 계정에 **비공개(private)** 로 복제합니다(`POST /voices/clone`, `language=ja`, `accent=standard-japanese`).
- 매니페스트의 `addAccents`(현재 `korean`)를 같은 voice에 더합니다(`PATCH /voices/{id}/accents`). Cartesia는 추가한 억양을 `is_native: false`로 돌려주며, 원래 억양이든 추가 억양이든 그 억양을 지원하면 준비된 것으로 봅니다.

음성 복제는 복제가 허용되는 Cartesia 유료 플랜(Pro 이상)에서만 됩니다. 플랜이나 크레딧이 막으면 준비를 멈추고 그 이유를 창에 보입니다. 참조 음성의 라이선스는 [ACML 1.0](../public/audio/live/ACML-1.0.txt)이며, 출처와 제작자는 [`public/audio/live/voices.json`](../public/audio/live/voices.json)의 `attribution`에 있습니다.

### 다시 준비해도 중복 복제하지 않는다

복제는 크레딧을 쓰므로 같은 캐릭터를 두 번 만들지 않도록 다음을 지킵니다.

- 단계마다 결과를 즉시 저장하고, 이미 준비된 캐릭터는 provider를 다시 부르지 않습니다.
- 새로 복제하기 전에 늘 **소유 voice 전체 목록**(`GET /voices?is_owner=true`, `starting_after` 페이지 넘김)을 읽어, description이 이 캐릭터·이 참조 음원의 표식(`CUELO live voice <id> ref:<sha256 앞 12자>`)과 **정확히 같은** voice를 재사용합니다. 목록의 `q` 검색 동작에는 기대지 않습니다.
- 응답을 받지 못한 복제(시간 초과·연결 끊김·5xx)는 같은 실행에서 다시 보내지 않습니다. 목록에서 결과를 찾으면 그 voice를 쓰고, 찾지 못하면 **확인 필요**로 남깁니다. 다음 준비는 목록을 먼저 다시 맞춰 본 뒤에야 복제합니다.
- 목록을 끝까지 확인하지 못하면(형식 오류·페이지 상한) 준비를 멈춥니다.
- 참조 음원 파일이 바뀌면 그 캐릭터만 새 표식으로 다시 복제합니다. 계정에 남은 예전 voice는 지우지 않습니다.

## 저장 위치

| 무엇 | 어디 | 비고 |
|------|------|------|
| Cartesia API 키 | AuthStorage `cartesia` (`type: "api_key"`) | CLI와 같은 저장소·락. 화면·응답에는 `sk_car_…abcd` 모양으로만 나갑니다 |
| 캐릭터별 voice 매핑 | `<agentDir>/cuelo-live-voices.json` | 0600·원자적 교체. 키 원문은 없고 키 지문(sha256 앞 16자)별로 나뉩니다 |

공개판 코드와 매니페스트에는 키도 voice id도 들어 있지 않습니다. 키를 지우면 매핑은 남지만 통화는 기본 음성으로 돌아가고, 같은 키를 다시 넣으면 기존 매핑을 그대로 씁니다. 다른 키(다른 계정)는 따로 준비합니다.

매핑 파일 형식:

```json
{
  "version": 1,
  "accounts": {
    "<키 지문>": {
      "acknowledgedAt": "2026-10-01T00:00:00.000Z",
      "characters": {
        "yuki": { "voiceId": "<private voice id>", "referenceSha256": "<참조 음원 sha256>", "accentsReady": true }
      }
    }
  }
}
```

다른 경로로 이미 만든 비공개 voice를 들여올 때는 그 캐릭터 항목에 `"voiceId": "…", "imported": true`를 적습니다. 들여온 항목은 참조 음원 비교를 하지 않고, 다음 준비가 `GET /voices/{id}`로 `addAccents`를 확인한 뒤(없으면 더한 뒤) `accentsReady`를 채웁니다. 깨진 매핑 파일 위에서는 준비를 시작하지 않습니다 — 빈 상태로 덮어쓰면 이미 만든 voice를 잊고 다시 복제하기 때문입니다.

## 캐릭터와 생성 설정

`public/audio/live/voices.json`이 캐릭터마다 참조 음원·억양·생성 설정(`generation_config`)을 정합니다. 파서는 id·별칭 짝, 같은 폴더의 파일 이름, `speed` 0.6–1.5, `volume` 0.5–2.0, Cartesia 감정 목록을 확인하고, 형식이 깨진 캐릭터만 「자산 없음」으로 둡니다.

| 캐릭터 | emotion | speed | volume | 상태 |
|--------|---------|-------|--------|------|
| YUKI(유키) | excited | 1.2 | 1.0 | 사용자 청취로 확정 |
| ISANA(이사나) | excited | 1.1 | 1.0 | 임시(청취 전) |
| MIO(미오) | calm | 0.95 | 1.0 | 임시 |
| RIN(린) | neutral | 1.0 | 1.0 | 임시 |
| NOVA(노바) | excited | 1.15 | 1.0 | 임시 |
| SHION(시온) | calm | 0.95 | 1.0 | 임시 |
| HIKARI(히카리) | content | 1.1 | 1.0 | 임시 |

임시 설정은 통화 중 「임시 음색」으로 표시됩니다. Cartesia 문서상 감정 지시는 영어에서만 보장되므로, 한국어 발화에서의 효과는 실제 청취로 판단합니다. SHION은 WEB6 상담 전용이라 Main으로 교체할 수 없어, 음성은 준비되지만 통화 캐릭터로 고를 경로는 없습니다.

## 통화 중 동작

- **누가 말하는가.** 통화를 시작할 때 서버가 이 세션의 Main을 정합니다. 규칙은 화면 얼굴과 같습니다. 캐릭터가 하나로 예약된 provider는 계정 수와 관계없이 그 캐릭터입니다(Codex→YUKI 등). Anthropic은 **이 세션에 pin된** OAuth 계정의 저장 순서로 정합니다(0→RIN, 1→MIO). 같은 모델을 쓰는 두 세션이 동시에 열려 있어도 각자의 pin으로 갈립니다. pin이 아직 없으면 추측하지 않습니다.
- **준비 안 됨.** 키는 있지만 그 캐릭터 음성이 준비되지 않았거나 캐릭터를 정하지 못하면, 다른 캐릭터 목소리로 대신하지 않고 기본 Codex 음성으로 통화하며 그 사유(「MIO(미오) 음성 미준비 · 기본 음성」)를 보입니다.
- **캐릭터 음성 통화.** 서버가 Codex의 assistant 전사를 받아 Cartesia WebSocket(`/tts/websocket`, `pcm_s16le` 24 kHz)으로 합성하고, 그 PCM을 통화 이벤트 스트림으로 브라우저에 보냅니다. 브라우저는 Codex 원격 음성 트랙을 연결하지 않으므로 두 목소리가 겹치지 않습니다. 합성할 텍스트는 서버가 받은 전사뿐이며, 브라우저가 텍스트를 보내는 경로는 없습니다.
- **끼어들기.** assistant가 말하는 동안 사용자가 새로 말하기 시작해 그 발화의 전사가 들어오면, 서버가 진행 중인 Cartesia context를 취소하고 epoch를 올립니다. 브라우저는 예약된 소리를 멈추고 이전 epoch 청크를 버립니다. 응답이 시작된 뒤 늦게 도착한, 지금 답하고 있는 사용자 발화의 나머지 전사는 끼어들기로 보지 않으므로 응답을 끊거나 다시 말하게 하지 않습니다. 연결이 열리기 전에 쌓여 있던 옛 발화 프레임도 버리므로, 끼어든 뒤 옛 답이 합성되지 않습니다.
- **Main 전환.** assistant 응답마다 첫 프레임(부분 전사든 final만 오는 턴이든)을 보내기 전에 Main을 다시 확인하고, 위임 턴이 끝난 뒤에도 확인합니다. 네이티브 통화는 사용자 최종 턴보다 assistant 부분 전사를 먼저 보내기도 하므로, 확인은 사용자 턴이 아니라 응답 시작에 걸려 있습니다. 확인하는 동안 들어온 답은 순서대로 기다렸다가 확인이 끝난 뒤 보냅니다. 그래서 새 Main의 첫 마디도 이전 캐릭터 목소리로 나가지 않습니다. 확인은 응답 하나에 한 번입니다. 응답 도중 Main이 바뀌면 다음 응답부터 반영됩니다. 새 캐릭터가 준비돼 있으면 이전 캐릭터의 남은 소리를 먼저 지우고 그 목소리로 말합니다. 준비되지 않았거나 Main을 확인하지 못하면 이전 목소리로 이어 가지 않고 사유를 보인 뒤 통화를 끝냅니다. 통화가 기본 음성으로 시작했으면 끝날 때까지 기본 음성입니다.
- **오류.** 크레딧 소진 같은 Cartesia 오류나 말하는 중 연결 끊김이 생기면 조용히 무음이 되지 않습니다. 「캐릭터 통화 음성을 만들지 못해 통화를 끝냈습니다」를 보이고 통화를 끝냅니다. 쉬는 중 연결이 끊기면 다음 발화가 다시 연결합니다. 오류 문구에 API 키가 섞여 오면 지운 뒤 저장하고 표시합니다.

## 확인되지 않은 것

- 브라우저 에코 제거(AEC)가 WebAudio로 재생한 캐릭터 음성을 상쇄하는지는 실제 통화로 확인하지 않았습니다. 스피커로 통화할 때 캐릭터 음성이 자기 발화로 잡혀 끼어들기가 생길 수 있으며, 헤드셋은 해당하지 않습니다.
- 끼어들기 신호는 사용자 발화 전사가 처음 들어온 때입니다. 실제 말 시작보다 늦을 수 있습니다.
- 무자격 플랜의 복제 오류 status(402/403으로 처리), 크레딧 소진 때 WebSocket 오류 형식, WebSocket 유휴 종료 시간은 문서로만 확인했습니다.
