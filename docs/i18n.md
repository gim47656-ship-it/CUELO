# 다국어 지원

CUELO 인터페이스는 자체 i18n 레이어를 사용합니다. 현재 내장 언어는 한국어(`ko`), 영어(`en`), 중국어 간체(`zh-CN`)입니다. 브라우저 언어를 바탕으로 기본 언어를 고르며, 사용자는 상단의 언어 선택 메뉴에서 바꿀 수 있습니다. 선택 언어는 `localStorage`의 `pi-locale` 키에 저장됩니다.

## 컴포넌트에서 번역 사용하기

Client Component에서는 `useI18n` hook에서 `t`를 가져옵니다.

```tsx
import { useI18n } from "@/hooks/useI18n";

export function ExampleButton() {
  const { t } = useI18n();
  return <button aria-label={t("example.open")}>{t("example.open")}</button>;
}
```

컴포넌트는 `I18nProvider` 아래에서 렌더링되어야 합니다. 실행 중 바뀌는 값을 문장 일부와 이어 붙이지 말고 interpolation을 사용합니다.

```tsx
<span>{t("session.messageCount", { count: messageCount })}</span>
```

각 메시지는 `{count}` 같은 placeholder를 포함할 수 있으므로 문장 순서는 언어별로 자연스럽게 조정합니다.

## 번역 문구 추가·수정

1. `lib/i18n/messages/ko.ts`, `en.ts`, `zh-CN.ts`의 대응 key를 함께 갱신합니다.
2. `chat.*`, `files.*`, `settings.*`, `common.*`처럼 기능별 namespace를 사용합니다.
3. 화면에 보이는 문구뿐 아니라 `title`, `aria-label`, `placeholder`도 번역 key를 사용합니다.
4. 수량·이름·경로 등 실행 중 값은 interpolation으로 전달합니다.
5. 제품명, 모델·provider 이름, 명령, 경로, 사용자 내용, 도구 출력, 서버 오류는 임의로 번역하지 않습니다.
6. API 오류의 영어 문구를 비교해 번역하지 말고, 앱이 제공하는 사용자용 fallback 문구만 번역합니다.

번역 key가 현재 언어에 없으면 영어 메시지를 사용하고, 영어에도 없으면 key 자체를 반환합니다. 개발 모드에서는 누락 key를 console warning으로 표시합니다.

저장소에 등록된 언어 목록과 번역 메시지는 `lib/i18n/types.ts`, `lib/i18n/registry.ts`, `lib/i18n/messages/`에 있습니다. 언어를 추가할 때는 메시지 파일을 만들고 registry에 등록한 뒤 `Locale` 타입과 UI 언어 선택 동작을 함께 확인합니다. 현재 구현은 한국어·영어·중국어 간체 세 내장 언어를 대상으로 하므로, 그 밖의 언어는 등록 및 검증 없이 지원된다고 가정하지 마세요.

관련 코드: `lib/i18n/`, `hooks/useI18n.tsx`, `app/layout.tsx`.
